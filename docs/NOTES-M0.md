# M0 notes: design gaps found while building the scaffolding

DESIGN.md is unchanged. Each item names the choice the M0 code made and a proposal for
DESIGN. Code locations are given so the choice is easy to revisit.

## Build and test

```
tools/test.sh                      # configure + build + ctest (conda env `immerdink`)
IMMERDINK_CUTLASS_DIR=/path/to/cutlass tools/test.sh   # if the submodule is not checked out
```

The constant header `include/immerdink/detail/constants.hpp` is generated by
`python3 spec/params.py --emit-header <path>`. The build regenerates it into
`build/generated/include`, and the test `constants_header_current` fails if the committed
copy is stale.

## DESIGN text and API gaps

1. **§2 L32 table.** DESIGN says "`L32` = 2 for N ≤ 7". The stated definition (minimal L32
   with `2P ≤ 2^{32·L32}`) gives **1 for N = 2, 3** (2P = 130560 and 33031680). The header
   emits the minimal value, per the definition (`kTables.L32`). Proposal: "1 for N ≤ 3,
   2 for N ≤ 7, …". The oracle's fixed 128/160-bit word is also valid, since any width at
   or above the minimum works.
2. **§2 "the only producer of the device constant tables (`--json`)".** The producer is now
   `--emit-header`. `--json` is unchanged. Proposal: name both.
3. **§6 lifecycle.** §6 has no way to create or destroy a handle or plan. M0 adds
   `imd_create`, `imd_destroy`, `imd_plan_destroy` and `imd_status_string`
   (`include/immerdink/immerdink.h`). Proposal: list them in §6.
4. **No allocation-failure status.** A failed host allocation in `imd_plan_create`
   returns `IMD_STATUS_CUDA_ERROR` (`src/api.cpp`). In M1 the plan's pinned buffers
   come from `cudaMallocHost`, which fails the same way. Proposal: state this mapping, or
   add `IMD_STATUS_ALLOC_FAILED`.
5. **§5 row 5 is not precise.** The code checks, all as INVALID_VALUE (`src/index_map.cpp`):
   - each tensor's element span `Σ|s|(e−1)`, for a non-empty tensor;
   - each merged diagonal stride (a sum of strides);
   - the lowered m, n, k and b;
   - the lowered operand sizes b·m·k, b·k·n and b·m·n fit int64;
   - `m ≤ 2³¹−1` and `n̂ ≤ 2³¹−1`, **always**, including DIRECT mode and an empty
     output, because the table has no exemption for either;
   - the §4a total, and every region size, fit uint64.

   Proposal: list exactly these checks. Also decide whether the GemmCoord limits apply to
   DIRECT mode or an empty C. DESIGN gives a no-op (0 bytes) for an empty C, but row 5 can
   reject it first when m > 2³¹−1.
6. **The workspace depends on C's strides.** §5 step 8's coalescing swap exchanges m and n,
   and §4a is not symmetric in them (n is padded to n̂; RA/RB/W differ). So
   `imd_workspace_size` must run the swap, and the swap needs C's fastest label to be
   unique. Row 4 (the sorted-|stride| rule) guarantees that: it forces strictly increasing
   |stride| over modes with extent > 1. M0 therefore implements rows 1–5 in precedence
   order, including the stride rule, together with the swap decision. The canonical
   orders, fusion and scatter vectors are M2 TODOs.

   Proposal: state in §5 step 8 that the swap looks only at C's modes with extent > 1;
   that it does not swap when there are none or when the fastest label is in L or J; and
   that the swap is part of §4a's m and n. The IndexMap TLA+ model does not cover the swap
   yet (a known follow-up).
7. **The `imd_contract` status order** outside the §5 table (`src/api.cpp`) is:
   1. null plan → INVALID_VALUE;
   2. empty output → SUCCESS, touching nothing, so null pointers are accepted;
   3. null C, or null A/B when they are read (α ≠ 0 and k ≠ 0), or null ws when
      `workspace_size > 0` → INVALID_VALUE;
   4. ALIASING (M3 TODO);
   5. MISALIGNED;
   6. `ws_bytes < workspace_size` → INSUFFICIENT_WORKSPACE.

   Proposal: add these rows to the table. Also decide whether the "workspace ∩ A/B/C"
   aliasing test uses `ws_bytes` or the required size. The required size is the exact
   region the library touches.
8. **The RN acceptance rule (§3.2, κ ≥ T → NOT_SUPPORTED)** is applied in
   `imd_plan_create`, and only when the emulated GEMM runs (EMULATE, k > 1, non-empty
   output). `imd_workspace_size` does not apply it, because it is exactly §4a.
   Proposal: say so in §3.2 and §6.
9. **The §3.6 `y = (q_l·W_l) mod p_l` constant-divisor reduction** needs no new constant.
   With `n = q_l·W_l < 2¹⁶`, the §3.5 umulhi64 constant `⌈2⁶⁴/p⌉` is exact by the same
   proof (`n·e < 2⁶⁴`, with bias 0). Proposal: M1 reuses it and adds a line to
   `cert_barrett`.

## CUTLASS findings (runtime, RTX 4090, nvcc 13.4, CUTLASS v4.8.0)

- The §4 configuration runs and is bit-exact against a CPU reference (`test_cutlass_int8_gemm`):
  - GemmUniversal kBatched, Sm80 on sm_89, int8 TN, OpMultiplyAddSaturate, int32 out.
  - `.satfinite` is confirmed: K = 131072 with all −128 gives INT32_MAX instead of 2³¹.
    At K = K_c' the extreme sums are exact.
- **The mod-p → u8 epilogue works at runtime** (`test_cutlass_mod_epilogue`):
  - Built from a custom Sm80 EVT node, `imd::kernels::VisitorModP`
    (`src/kernels/mod_epilogue.cuh`), with `l = g0 + z / b` read from `__constant__`.
  - Store-mod is `Sm80EVT<AuxStore<u8>, VisitorModP>`. Add-mod is
    `Sm80EVT<AuxStore<u8>, Sm80EVT<VisitorModP, AuxLoad<u8>>>`, in place on the W planes.
  - Bit-exact against CPU for:
    - all 20 moduli in one launch, b = 2, 3 chunks;
    - a mid-table group (g0 = 5, |G| = 3, b = 3) over 2×2 tiles with predicated M;
    - the exact reachable extremes v_min and v_max of every modulus at K = K_c'.
  - Planes outside the group are untouched. The tile is 128×256×64 with 3 stages (72 KB
    smem).
  - Mutations are caught: dropping the add, `z % b` instead of `z / b`, and a wrong magic.
- `imd::device::mod_p` (bias + umulhi64, or a mask for 256) is checked **exhaustively on the
  GPU** over every reachable input of every modulus: 6.37·10¹⁰ values in about 0.3 s
  (`test_device_constants`). This covers PLAN M1's "exhaustive epilogue" item on the device
  side. The CPU-vs-oracle version is still to do.
- Gotchas:
  - `cutlass/epilogue/threadblock/fusion/visitors.hpp` is not self-contained. Include
    `default_gemm_universal_with_visitor.h` first.
  - `static __constant__ Tables c = kTables;` (static initialization from a constexpr
    aggregate) works in nvcc 13.4. Each CUDA TU gets its own 13.5 KB copy.
  - The K-chunk offset is applied as a pointer offset (`A + k0`, with `lda = k̂`). It
    relies on k0 being a multiple of 16, which K_c' is.
