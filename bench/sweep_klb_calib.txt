# fit with the key. Geometry of the KL launch (src/host/analysis.hpp kl_launch): a pack read along
# rows takes th = 8 rows x tk = 512 per tile, nc = ceil(k_hat / 512) chunks, one CTA per tile, so
# 'ik,kj->ij' with a narrow j puts B on the multi-pass launch (nc >= 3; KL4, 1 CTA/SM resident,
# waves = ceil(tiles / 128)); 'ik,jk->ij' reads B along k (tk = pow2 >= k_hat, capped at 4096:
# nc = 1 for k_hat <= 4096, 2 up to 8192; KL8 with values = 8 for nc <= 2). What each group identifies:
#   nc      k = 1088 .. 6144: nc = 3, 4, 5, 6, 7, 8, 12 (all KL4, values = 4: nc*g and nc*values*g differ
#           by a constant there; only the nc <= 2 rows below, values = 8, can tell them apart)
#   nc12    B along k, nc = 1 and 2 (values = 8): k_bnc1, k_bnc2
#   waves   j = 1024 / 1032 / 2048 / 2056 at nc = 3: tiles 128 / 129 / 256 / 257 (waves 1, 2, 2, 3). These are
#           DRAM-bound (chain arm / byte arm about 0.2): they test that the max does not fire there
#   cross   j = 128 .. 8192 at nc = 3: chain arm / byte arm about 0.2 .. 2 (at 0.22 us per nc*g unit); a ratio
#           near 3 needs nc >= 4. j = 320 puts a row near 1
#   g       g = 2, 4 at N = 5, 9, 13 (g < N, separate g from N). Expect a g-independent per-chunk part too:
#           the shipped kl.wave may be too small for KL4 narrow launches (DESIGN §6c.10)
#   side    KL A narrow, nc = 1 (ik,kj) and multi-pass (ki,kj; nc >= 3), B along k, a batch label, a tensor
#           spec, imd_pack's KL (method packed)
#   cold    --l2 flush: call TOTALS only (the phase marks stay REPEAT state; the records' prediction state is
